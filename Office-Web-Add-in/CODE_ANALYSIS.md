# 🔍 วิเคราะห์โค้ด Gemini Assistant — Word Add-in (Conversational Edition)

> เอกสารนี้วิเคราะห์โครงสร้างโค้ด สถาปัตยกรรม และฟังก์ชันการทำงานทั้งหมดของโปรเจกต์อย่างละเอียด  
> อัปเดตล่าสุด: เวอร์ชัน 1.0.4 (เพิ่มปุ่มตรวจสอบเทียบไฟล์แนบ)

## 📁 สรุปไฟล์ในระบบปัจจุบัน

โปรเจกต์ประกอบด้วยไฟล์สำคัญ 5 ไฟล์หลักที่เชื่อมโยงถึงกัน:

```
[ manifest.xml ] ── Word อ่านข้อมูลแอปและ URL หลัก
       │
       ▼
[ taskpane.html ] ── โครงสร้างหน้า UI แบบกล่องแชทโต้ตอบ
   ├── โหลด mammoth.js, xlsx.js, pdf.js (CDN) สำหรับดึงข้อความจากไฟล์ภายนอก
   ├── เชื่อมสไตล์ [ taskpane.css?v=1.0.4 ] (ธีมมืดและปุ่มตรวจสอบเทียบไฟล์)
   └── เรียกคำสั่งควบคุม [ taskpane.js?v=1.0.4 ] (ตรรกะและฟังก์ชันเปรียบเทียบ)
```

## 📄 ไฟล์ที่ 1: `manifest.xml`

ไฟล์ลงทะเบียนแอปพลิเคชันเพื่อบอกให้ Word ทราบถึงข้อมูลพื้นฐาน:
*   **การกำหนดสิทธิ์:** กำหนดระดับสิทธิ์เป็น `ReadWriteDocument` ซึ่งอนุญาตให้ Add-in สามารถอ่านและเขียนทับตัวหนังสือในหน้ากระดาษได้
*   **การตั้งค่าเซตฟังก์ชัน:** เลือกใช้ `WordApi 1.1` เป็นขอบเขตหลัก ซึ่งรองรับคอมโพเนนต์การดึงบอดี้กระดาษทั้งหน้า

## 📄 ไฟล์ที่ 2: `taskpane.html` (โครงสร้าง UI แชท)

โครงสร้างหน้าเว็บแอปพลิเคชันได้รับการปรับปรุงเพิ่มคอมโพเนนต์ตรวจสอบเทียบไฟล์แนบ:
*   **ปุ่มเปรียบเทียบ (`#btnCompare`):** ถูกจัดวางไว้เหนือแถบกล่องแชทด้านล่างสุดของหน้าต่าง เพื่อให้อยู่ใกล้กับรายการป้ายบอกชื่อไฟล์แนบและกล่องอินพุต สะดวกต่อการเรียกใช้งาน
*   **Cache Buster (v1.0.4):** ลิงก์เชื่อมโยงไปยัง CSS และ JS ถูกเปลี่ยน query parameter เป็น `?v=1.0.4` เพื่อบังคับให้ Microsoft Word ล้างแคชเก่าทิ้งและโหลดสไตล์รวมถึงสคริปต์ตัวเปรียบเทียบไฟล์ล่าสุดไปประมวลผล

## 📄 ไฟล์ที่ 3: `taskpane.css` (สไตล์ปุ่มตรวจสอบเปรียบเทียบ)

*   **ปุ่มเปรียบเทียบ (`.compare-btn`):** ถูกตกแต่งให้กว้างเต็มพื้นที่ (`width: 100%`) โดยใช้สีครามฟ้าหลักของแชท (`var(--color-primary)`) บนพื้นหลังการ์ดสีเข้ม
*   **เอฟเฟกต์แอนิเมชัน:**
    *   เมื่อชี้เมาส์ (`:hover`): เปลี่ยนสีพื้นหลังเป็นสว่างขึ้นเล็กน้อยเพื่อแสดงสถานะพร้อมกด
    *   เมื่อกดคลิก (`:active`): ขยับขนาดหดตัวเล็กลง 2% (`transform: scale(0.98)`) เพื่อสร้างความรู้สึกในการกดปุ่มจริง (Tactile Feedback)
    *   เมื่อถูกปิดการใช้งานขณะรันระบบ (`:disabled`): เปลี่ยนค่าความโปร่งใสเป็น 55% และเปลี่ยนเคอร์เซอร์เมาส์เป็นรูปห้ามกด
*   **เลย์เอาต์หลัก:** ปรับเพิ่มระยะห่างช่องว่างขอบล่างของตัวจัดเก็บแชทหลักเป็น `170px` เพื่อให้กล่องแชทและปุ่มเปรียบเทียบข้อมูลลอยตัวอยู่ด้านล่างโดยไม่ทับซ้อนข้อความแชทตัวสุดท้าย

## 📄 ไฟล์ที่ 4: `taskpane.js` (ตรรกะการวิเคราะห์เทียบข้อมูลอ้างอิง)

สถาปัตยกรรมตรรกะตัวช่วยตรวจสอบเปรียบเทียบได้รับการออกแบบเพิ่มเติมผ่านฟังก์ชัน `handleCompareAction()`:

### 1. การดักจับและตรวจสอบความพร้อมก่อนเรียกใช้ (Error Handling)
ก่อนส่ง API ระบบจะทำการเช็คเงื่อนไข 2 ชั้น:
*   **ตรวจสอบไฟล์แนบ:** ตรวจสอบจาก Array `uploadedFiles.length === 0` หากไม่มีไฟล์อัปโหลดอยู่ ระบบจะแสดงผลสถานะแจ้งเตือนสีแดงเตือนให้แนบไฟล์และยกเลิกกระบวนการทำงานทันที
*   **ตรวจสอบ API Key:** หากช่องกรอก API Key ว่างเปล่า ระบบจะสไลด์แผงตั้งค่าลงมาให้อัตโนมัติเพื่อให้ผู้ใช้กรอกคีย์ก่อนใช้งาน

### 2. การผูกโครงสร้างคำสั่งประมวลผลเบื้องหลัง (Hardcoded Prompt Template)
ระบบจะผูก Prompt คำสั่งที่กำหนดบทบาทผู้เชี่ยวชาญราชการและงานสารบรรณเข้าไปโดยอัตโนมัติ โดยโครงสร้าง Payload ที่ส่งหา API มีดังนี้:
```javascript
var baseComparePrompt = "[ข้อความระเบียบงานราชการและ 5 เงื่อนไขการตรวจสอบ]";
var fullComparePayload = baseComparePrompt;

// 1. แนบตัวอักษรที่แกะได้จากไฟล์ประกอบทั้งหมด
fullComparePayload += "\n\n=== [เอกสารอ้างอิง] ===" + [ตัวอักษรของไฟล์แนบทั้งหมด];

// 2. แนบตัวอักษรจากบอดี้ของ Word ปัจจุบัน
fullComparePayload += "\n\n=== [เอกสารหลัก Word] ===" + [ตัวอักษรของ Word];
```

### 3. การผูกเข้าประวัติสนทนาหลัก (Chat History Integration)
*   เมื่อผู้ใช้กดปุ่มเปรียบเทียบ ระบบจะจำลองตัวอักษรแชทฝั่งผู้ใช้ว่า `"🔍 ตรวจสอบเทียบไฟล์แนบ: [รายชื่อไฟล์]"` พ่นลงในกล่องหน้าต่างแชทเพื่อแสดงความคืบหน้า
*   ข้อความ Prompt เปรียบเทียบข้อมูลทั้งหมดจะถูกส่งลง Array `chatHistory` เป็นข้อแรกของการเริ่มคุยแชท ทำให้ AI จดจำข้อมูลเอกสารหลักและข้อมูลเปรียบเทียบได้ในหน่วยความจำ
*   ผลการวิเคราะห์ที่ได้รับจาก Gemini จะถูกพ่นออกมาเป็นฟองคำพูด AI แถบซ้าย พร้อมมีปุ่ม **`แทรกที่เคอร์เซอร์`**, **`เขียนทับ`**, และ **`คัดลอก`** ติดมาด้วย ทำให้ผู้ใช้สั่งงานโต้ตอบต่อเนื่องต่อจากข้อสรุปนั้นได้ในทันที

## 📄 ไฟล์ที่ 6: `highlightReview.js` (โมดูลควบคุมสีและคอมเมนต์)

สถาปัตยกรรมการตรวจอัจฉริยะ (Smart Review) และการระบายสีข้อบกพร่องแบ่งหน้าที่การทำงานอย่างชัดเจนดังนี้:

### 1. ฟังก์ชัน `callGeminiReview(documentText, apiKey, model)` (ใน taskpane.js)
*   ส่ง Prompt ระบุบทบาทผู้เชี่ยวชาญด้านภาษาไทยและตรวจคำผิด
*   ส่งคำสั่งบังคับผลลัพธ์ผ่าน `"responseMimeType": "application/json"` เพื่อรับรองว่าจะได้อาร์เรย์ของ JSON กลับมาเท่านั้น (Spelling, Spacing, Grammar, Ambiguity, Duplicate, OfficialFormat)
*   รักษากฎเหล็กห้ามตรวจสอบประเด็นตัวเลขไทยปนอารบิก

### 2. ฟังก์ชัน `renderReview(reviewData)` (เรนเดอร์ UI ใน taskpane.js)
*   นำข้อมูล JSON รายการคำผิดมาวนลูปวาดสร้างเป็น `review-card` บนช่องแชท
*   สร้างปุ่มหลักด้านบน: `🖍 Highlight ทั้งหมด` และ `🧹 ล้าง Highlight`
*   สร้างปุ่มการ์ดย่อย: `✔ แก้ไขเฉพาะจุด` และ `🖍 ไฮไลท์` เฉพาะคำ

### 3. ฟังก์ชัน `applyReview(oldText, newText)` (แก้ไขเฉพาะจุดใน taskpane.js)
*   ค้นหาคำสะกดผิดเดิม (`oldText`) ในเอกสารโดยใช้ `searchResults = context.document.body.search(...)` ของ Office.js
*   แทนที่ตัวอักษรด้วยคำใหม่ (`newText`) ด้วย `insertText(newText, "Replace")` เฉพาะจุดที่พบเท่านั้น โดยไม่ลบและไม่เขียนทับเอกสารหน้าอื่น เพื่อความปลอดภัยของข้อมูลผู้ใช้

### 4. ฟังก์ชันจัดการกระดาษใน `highlightReview.js`
*   **`highlightItem`:** ระบายข้อความผิดในกระดาษเป็นสีเหลือง (`Yellow`) และใส่กล่องคอมเมนต์ของ Word ด้วย `range.insertComment()` หากเวอร์ชัน API เป็น 1.4+
*   **`highlightAllItems`:** ลูปรันและสลักจุดผิดทั้งหมดในคลิกเดียว พร้อมแจ้งเตือนลิสต์ของคำที่ไม่พบบนหน้าจอ
*   **`clearAllHighlights`:** ล้างไฮไลท์ทั้งบอดี้คืนค่าเป็นปกติด้วยการกำหนดค่า `body.font.highlightColor = null`
